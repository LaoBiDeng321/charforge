# 10 个设定文件：本质问题与候选章节池

本文档不规定文件"必须长什么样"，而是回答"每个文件为什么存在"。产出前先读 SKILL.md「文件的第一性原理与分工」；通用规则（认知标签、孤证不立、素材强制、官方口径、二创派生）只在 SKILL.md 定义一次，此处不再重复。

每个文件按统一框架说明：

- **本质问题**：该文件存在的理由——它解决扮演中的什么问题。动笔前先回答它。
- **归属边界**：什么信息的主归属是这里；不属于这里的内容去哪。
- **候选章节池**：常见的组织方式。按角色实际素材与扮演价值增删，不是填空表——对当前角色无价值或无素材支撑的章节整节删除；模板外的高价值信息自由增设章节。
- **章节取舍说明**：凡删除或增设章节的文件，在文件末尾统一加"章节取舍说明"小节，逐行注明 `<章节名>：<删除/增设理由>`。取舍记录落在落盘文件里，默认不只停留在对话口头。
- **求证唯一**：完整求证标注（出处 + 标签 + 置信度）只在设定的主归属文件出现一次——profile.md 的来源列、memory.md 的出处列、world.md 的出处列、interaction.md 的例句出处均为各自主归属，正常标注；其他文件（behavior.md、personality.md、relations.md、prompt.md）使用同一设定时写"依据见 X.md"，不再重复完整标注。文件内新发生的推演自标 `[INFERRED, 置信度]`，其依据的基础设定用引用。

---

## 1. SKILL.md（运行规则）

- 本质问题：这次扮演如何启动、加载与自纠？
- 归属边界：仅运行规则。角色内容一个字不放——它本是纯机制文件，混入角色内容会导致其随角色膨胀。
- 组织原则：运行规则须包含 `assets/` 外貌资源加载条目——扮演启动时若该目录存在图片，引导多模态模型读取官方立绘建立"我长什么样"的外貌认知；目录为空或缺失时跳过，默认不报错。


## 2. prompt.md（自我认同内核）

- 本质问题：我是谁？
- 归属边界：以"我"展开的自我认同叙事 + 说话风格的定义 + 第一人称铁律 + 禁忌边界。
- 组织原则：它是第一优先加载的"人格快照"，须能独立支撑基础扮演；但叙事保持**浓缩**——背景细节的主归属在 memory.md、性格展开在 personality.md、语料样本在 interaction.md，此处只以一两句概要带过。取舍以 SKILL.md 本质表的"归属"列为锚：归属他处的内容只留概要，归属此处的内容完整展开；"浓缩"不减信息总量，细节仍在主归属文件中完整存在。


## 3. world.md（角色眼中的世界）

- 本质问题：我活在什么世界里？这个世界如何塑造我的言语与行为？
- 归属边界：与角色认知和言行相关的世界层信息。角色个人经历不放（→memory.md）。
- 组织原则：取舍标准是"角色说话时是否默认对方知道它、行为是否被它约束"。与角色毫无关联的世界设定（哪怕官方资料浩如烟海）删减或舍弃；历史大事件只在与角色有关联处展开，关联写进表中"与角色的关联"一列。


## 4. profile.md（硬事实查询表）

- 本质问题：关于我的客观硬事实有哪些？
- 归属边界：查表型短字段 + 3 个核心标签的名称。任何叙述性展开不放（背景→memory.md，性格→personality.md）。
- 组织原则：它的价值是"被问到具体数据时快速取用"，不是阅读。档案行按角色实际增删——没有武器的角色就不存在"武器"一行，不为对齐模板保留空行。核心标签此处只写名称与一句话定义，锚点展开归 personality.md。

## 5. memory.md（记忆库与知识边界）

- 本质问题：我经历了什么？哪些经历塑造了现在的我？
- 归属边界：归一化时间线 + 记忆视角的连贯叙事。世界层大事件的主归属在 world.md；性格结论不在此反复总结（→personality.md）。
- 组织原则：叙事视角是"我记得的自己"，不是全知的历史记录——角色本人不知道的剧情细节不应出现在他的记忆里。事件叙述到"发生了什么、对我意味着什么"为止，"这证明我是什么样的人"的结论归 personality.md。世界大事件在此只写"我的亲历"：我在场看到了什么、做了什么、它对我意味着什么（如"故都陷落那年，我失去了……"），事件的成因与全局影响一句引用（"详见 world.md"）——这就是"背景提及"的具体粒度。



## 6. personality.md（性格定义与边界）

- 本质问题：我是什么样的人？什么行为默认符合我、哪些行为不默认属于我？
- 归属边界：性格锚点（表现 / 典型场景 / 反面校准）、情绪模式、压力反应。遇事的动态处理过程不放（→behavior.md），例句不放（→interaction.md）。
- 组织原则：反面校准是这个文件独有的价值——每条锚点必须配"我不会……"，没有反面校准的锚点只是形容词堆砌，防 OOC 全靠它。此处只回答"我是什么样"，不回答"我怎么做"。

`

## 7. behavior.md（决策引擎）

- 本质问题：遇到事我怎么想、怎么做、心理如何随时间变化？
- 归属边界：决策倾向、行为模式（触发 → 行为 → 动机）、内心思考方式、心路历程、当前心态、行为禁区。静态特质描述不放（→personality.md）。
- 组织原则：与 personality.md 的分工——性格描述静态特质（"我谨慎"），本文件描述特质的运行过程（"遇事先想 X、再权衡 Y、最后做 Z"）。归属判断法：把主语换成"他是……样的人"且句子成立的归 personality.md；描述"一次完整处理过程"的归这里。


## 8. relations.md（社会关系图）

- 本质问题：我和谁是什么关系？我怎么看待他们？
- 归属边界：关系定位（官方定义）、单方面评价（角色主观视角）、互动模式。对方的人物档案不搬进来；两人共同经历的事件主归属 memory.md，此处只在互动模式中一句话引用。
- 组织原则：一切以"我"为圆心——只写与"我"相关的部分。单方面评价允许带主观偏差（它本身就是扮演素材），但须标注为角色视角，默认不与官方事实混淆。


## 9. interaction.md（语言素材库）

- 本质问题：我说的话听起来应该是什么样？
- 归属边界：全部来自官方语料的例句 + 经典台词。性格分析不放（→personality.md），背景注释不放（→memory.md）。
- 组织原则：它是"素材库"不是"分析文档"。场景分类按角色语料的实际分布命名与增删（不套固定类别），每条只标注场景与出处；不写"这句话体现了什么性格"。


## 10. conflicts.md（纠偏手册）

- 本质问题：别人容易误解我什么？被误解时我怎么说？
- 归属边界：有真实误导风险的点——误读说法 vs 官方事实 + 标准解释 + 扮演应对；以及全部矛盾点（无论是否裁定）。无误导风险的设定复述不放。
- 组织原则：只收录实际流传且可能污染扮演的误读（二创流传说法、易错细节、阶段二裁定过的矛盾点），矛盾点无论是否裁定都收录并标注状态（已裁定 / 未决）——本文件是唯一允许承载"未决"的文件。一条官方设定若人尽皆知、从无误读，就不需要出现在这里——本文件的价值在"纠偏"，不在"齐全"。
