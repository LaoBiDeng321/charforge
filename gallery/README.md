# 首屏背景画廊切片

首屏（hero）背景层「斜向滚动画廊」用的瓦片：**每张都是 `char/<slug>/assets/` 下素材的派生图**，
不是新素材、不参与任何角色卡的扮演设定。

```text
gallery/<slug>/NN.webp     # 归一化后的瓦片，NN 按 assets/ 文件名排序（只对未被排除的素材连续编号）
gallery/manifest.json      # 每张瓦片的来源、变换记录、口径参数 + 被排除的素材
gallery/exclude.json       # 排除清单：不上首屏的素材（原图仍在 char/ 里）
gallery/matte.json         # 抠图的**例外**清单（规则是自动的，见下节）
```

## 生成与更新

```bash
python tools/make_gallery.py            # 增量生成（默认；没变的瓦片整张跳过）
python tools/make_gallery.py --force    # 忽略缓存与上次结果，全量重做
python tools/make_gallery.py --check    # 只报告，不写文件
python build_data.py                    # 把瓦片清单写进 index.json（前端从这里取图池）
```

**它是增量的，不会每次都重跑模型。** 判断"要不要重做"看三条，全成立就整张跳过：
① 口径指纹（画布 / 质量 / 编码档位 / 阈值 / 羽化 / 抠图口径 / **matte.json 的 force·skip 清单**）与上次相同；
② 源图内容哈希与 `manifest.json` 的记录相同；③ 上次那张瓦片还在、字节数对得上（手改过就重做）。
三条成立时重做**必然**得到逐字节相同的结果——所以跳过是等价变换，不是"偷懒"。

抠图结果另存一份本地缓存（`gallery/.cache/`，键 = 抠图口径 + 源图哈希，已 gitignore）：
换了画布尺寸、改了编码档位这类**与抠图无关**的改动，只会重做裁切/缩放，不会再把模型拉起来。
模型只在"源图变了或抠图口径变了"时才真的跑。

实测（26 张瓦片、本机）：什么都没改 **0.2s**（复用 26 张、跑模型 0 次）；全量重做 **6s**
（跑模型 0 次，缓存命中）；真正需要重新抠图的只有改动过的那几张。

> 全量重做的耗时几乎全在 WebP 编码上，不在模型：编码档位 `method=6` 是 70s / 782KB，
> `method=4` 是 1.5s / 810KB（alpha 无损、像素 alpha 通道逐位相同，可见像素平均差 1.2%）。
> 取 4。**模型只占全量的约 4 秒。**

**什么时候必须重跑**：

- `char/<slug>/assets/` 增删或替换了图片（加角色、换立绘、下架某张图）；
- 改了 `gallery/exclude.json`（让某张素材不上首屏，见下节）或 `gallery/matte.json`（抠图例外）；
- 想换归一化口径（画布尺寸、质量、裁切锚点、羽化宽度）——改 `tools/make_gallery.py` 顶部常量后重跑。

两张都要提交入库：`index.json` 是入库的，GitHub Pages 没有构建步骤，
派生图不入库的话线上首屏就是一片空白。（Netlify 会跑 `build_data.py`，
但那只覆盖 Netlify。）

## 不想让某张素材上首屏：写 `exclude.json`，别删原图

观感上不适合当背景的素材（惊悚向的形态立绘之类）写进 [`exclude.json`](exclude.json)：

```json
{ "slug": "tachibana-sherry-manosaba", "file": "02-全身立绘-魔女化.png", "reason": "...", "since": "2026-09-22" }
```

- `file` 是 `char/<slug>/assets/` 下的文件名，逐字节精确匹配；
- **别删 `char/<slug>/assets/` 里的原图**：那是角色卡的外貌依据、随 ZIP 下发。这里排除的
  只是「作为首屏背景展示」这一件事，不影响角色卡、下载包与任何设定；
- 重跑后瓦片会被生成器自动清掉（`prune`），清单里的排除项同时写进 `manifest.json` 的
  `excluded`，所以"图池为什么少了一张"在产物里就有答案；
- 判断口径是**观感**，不是版权或可用性——素材本身没问题。

## 与缩略图是同一张图的素材：自动跳过，不用写清单

`assets/` 与 `thumbnails/` 是两条流水线（前者随 ZIP 下发给扮演用的 agent，后者是站点卡片封面），
所以"这张素材其实是缩略图"的唯一可靠证据是**内容哈希相同**。生成器按这个判：

> 素材若与 `thumbnails/<slug>/` 里的图**逐字节相同**，说明它就是缩略图/头像/表情包那一类
> （归属地是 `thumbnails/`，见 [`../docs/MAP.md`](../docs/MAP.md)「图片分三处」），
> **不进画廊图池**——原图照旧随角色卡下发，`manifest.json` 里记 `kind: "thumbnail"`。

实测命中的是三月七的 `10-头像-三月七.png`：它和
`thumbnails/march-7th-honkai-star-rail/cover.png` 是同一个文件（站点卡片封面就是它）。
这条路是写进代码的规则、不是一次性清名单：**以后谁再往 `assets/` 里放一张与封面重复的方形图，
重跑就会被自动挡住**，判断依据与实际产物来源一致（内容哈希），不会随着改名或换格式失效。

## 归一化规则（细节见 `tools/make_gallery.py` 头部注释）

源图尺寸从 600×600 到 4000×4218、体积最大 14 MB，直接上首屏不现实，所以统一压成 **360×480 的 WebP**。
判定全按**像素实测**，不看文件名、不写死清单——新增素材自动落到对应的路径：

| 路径 | 判定 | 处理 | 对齐 |
|---|---|---|---|
| **cutout** | 源图自带透明底（alpha 全透明占比 > 2%） | 按 alpha 紧裁 → 等比缩放进画布，透明底保留 | **水平居中、底边对齐**（立绘站在同一基线，滚动时不上下乱跳） |
| **matte** | 不透明，但**背景明显纯色**（外圈同色率 ≥ 0.90） | 交给本机 isnet-anime 抠底 → 与 cutout 同样收尾 | 同上 |
| **plate** | 其余（满幅插画 / 光锥 / 带框卡片 / 场景 / 实拍照片） | 等比铺满画布后裁切，再**四边羽化**到透明 | 横向居中、纵向 0.35（人像头部通常在上半部） |

### 为什么只对「明显纯色底」抠图

`isnet-anime` 是**主体分割**模型，只对"平底上的主体"有效。逐张试过（不是猜的）：
满幅插画它要么把整块背景一起留下（光锥、卡片、`cyrene 02/08`、`alf 01`），要么把主体抠没
（`march 04` 前景只剩 7%、`shu` 春日宴全图剩 15%），实拍照片直接糊成一团（`cyrene 11` 安踏联动）。
**这些抠完比不抠更难看**，所以它们走 plate 路径。

纯色底怎么判：缩到 256 内，取外圈 5% 的像素，与这圈的中位色相差 ≤14 的占比 ≥0.90 就算。
阈值是量出来的——本仓库实测非纯色底落在 **0.002 ~ 0.495**，纯白底是 **0.958 / 0.983**，
两侧余量都很大，不存在卡在边界上的图（每张的实测值都记在 `manifest.json` 的 `plainRatio`）。

判定与观感不一致时，往 [`matte.json`](matte.json) 的 `force`（该抠没抠）/ `skip`（抠了难看）里加一条，
**规则本身不改**。抠图依赖（`rembg` + `onnxruntime` + 本机模型）见 [`../docs/MODEL.md`](../docs/MODEL.md)：
它是本地工具链、不是站点运行依赖；但清单里有要抠的素材而本机没有 rembg 时，生成器**直接报错**，
不会静默产出一批没抠的瓦片。

### 为什么 plate 要羽化

图池里既有透明底立绘（浮空的人），也有铺满整块的图（硬边矩形）。两者在 16% 不透明度下
依然看得出差别——矩形会读成"一块块贴上去的板子"，混在一起不整齐。四边 smoothstep 渐隐之后，
整块图退成柔光色块，和人物是同一类元素。想改成"非纯色底的干脆不进图池"：
把 `tools/make_gallery.py` 的 `PLATE_MODE` 改成 `"skip"` 重跑（那样图池会只剩人物）。

输出恒为 WebP：这套图里只有 WebP 同时满足「体积小」与「保留透明通道」，
透明立绘存 JPEG 会把透明区压成色块，在近黑的首屏上就是一个洞。

## 别手改这个目录

- **不要手放图片**：`manifest.json` 与 `index.json` 都按这里的实际文件生成，手放会让溯源对不上。
- **不要手改瓦片**：要改口径就改脚本再重跑；下一张新素材进来时会覆盖你的手改。
- 瓦片本身**不是**任何角色卡的内容依据。扮演用的外貌依据始终是
  `char/<slug>/assets/`（见各角色 `assets/README.md`）。

## 溯源

`gallery/manifest.json` 逐张记录：`source`（源图相对路径）、`sourceSha256`（源图内容哈希）、
`sourceSize`、`mode`（cutout / matte / plate）、`plainRatio`（纯色底判据实测值）、
`matteForeground`（抠图前景占比，仅 matte）、输出体积；顶层的 `policy` 记录当次用的全部口径
参数（含抠图模型名）。任何一张瓦片都能据此回到源图与当时的算法——这是本目录的溯源凭证
（`_溯源/` 规则见 [`../docs/QUICKSTART.md`](../docs/QUICKSTART.md)）。

> 派生图**不新增溯源义务**：源图已经在 `char/<slug>/assets/` 下按各角色的收录记录与版权说明管理，
> 这里只是它的另一种尺寸。
